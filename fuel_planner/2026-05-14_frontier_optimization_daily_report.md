# 2026-05-14 日报：未知环境探索中的重复访问抑制与前沿选择优化

## 一、今日工作目标

今天主要围绕无人机未知环境探索中的重复访问问题进行分析和优化。当前系统在 FUEL 原始前沿选择方法的基础上，已经加入了凹陷区域代价、狭窄通道代价、路径洪水覆盖和遗忘区域优先探索机制。理论目标是让无人机在探索过程中尽量减少远距离回头补观测，降低全局路径重叠，提高未知区域探索效率。

但上一轮实验发现，无人机并没有稳定完成探索，而是在岔路口附近不断重规划，陷入局部最优。因此今天的重点不是继续增强局部回头能力，而是先分析为什么当前策略会在岔路口失效，并对代码进行“稳定性优先”的修正。

## 二、当前出现的问题

1. 无人机在岔路口难以稳定选择探索方向

上一轮实验只运行到 200 多轮，并不是因为地图探索任务很短，而是无人机在岔路口附近不断重规划，无法稳定进入某一个分支继续探索。这说明前沿选择策略在多分支场景下缺少方向保持能力，容易在多个候选前沿之间反复切换。

2. 局部遗忘区域优先级过高，干扰了正常分支探索

从 `local_view_log.csv` 中可以看到，很多被提升为局部优先目标的前沿并没有明显的覆盖遗忘证据。尤其是部分 `selected_reason=2` 的目标，其 `coverage_overlap` 接近 0，`progress_delta` 也接近 0，说明这些目标并不一定是真正需要立即补观测的遗忘区域。

这会导致局部 closeout 机制过于激进，把无人机从正常分支探索中拉回来，使无人机在岔路口附近反复处理低收益目标。

3. debt-only 遗忘判断产生误触发

上一版中，`debt_score` 可以单独触发遗忘标记。数据中出现了大量 `forget_reason=4`，说明很多前沿仅仅因为债务分数高就被标记为遗忘区域。但 `stale_fraction` 基本为 0，很多目标并没有真实失效，也没有充分的路径覆盖证据。

这类假遗忘会让局部规划器错误地认为附近存在大量必须优先处理的残留问题，从而压制正常探索。

4. 路径重叠惩罚影响了岔路口分支选择

上一版对路径 overlap 的计算偏向整条路径。岔路口场景中，进入不同分支前往往都需要先经过一段相同旧路径。如果直接用整条路径重叠作为惩罚，不同分支会同时被惩罚，导致代价区分能力下降，甚至让规划器反复在分支入口处犹豫。

5. cooldown 机制不够硬

虽然上一版加入了 cooldown，但在局部 closeout 中仍可能继续把低进展前沿提前，使同一个目标在短时间内反复被尝试。数据中能看到个别稳定前沿多次排在局部第一，`local_pass_cnt` 和 `attempt_cnt` 增长明显，但 `progress_delta` 很低。

## 三、今日优化思路

今天的核心思路是先恢复全局探索的稳定性，再保留必要的局部补观测能力。也就是说，不再让“遗忘修复”和“重复访问抑制”过度干扰 FUEL 原始 ATSP 的全局探索顺序。

具体原则如下：

1. 全局选择以稳定推进为主

全局前沿之间的 ATSP 代价默认恢复为 FUEL 原始代价，不再默认加入 debt、overlap、区域切换和回返惩罚。这样可以避免实验性代价在岔路口放大局部误判。

2. 局部修复只处理证据充分的目标

局部 closeout 不再根据 debt_score 单独触发，必须有路径覆盖、真实 forget 标记，或者非常近距离下的多次经过低进展证据。这样可以减少假遗忘目标对局部规划的干扰。

3. 岔路口需要方向保持机制

新增 branch hysteresis 思路：把局部范围内的前沿按无人机到前沿的方向划分为不同分支。一旦系统选择某个分支，就保持若干轮优先探索该分支，直到该分支没有候选或保持时间结束。这样可以降低岔路口左右摇摆。

4. 路径重叠惩罚只关注末端重复

将 overlap 从整条路径判断改为 tail overlap，只看路径末端约 3m 的重复覆盖，并且只有当前沿本身存在覆盖重叠时才产生惩罚。这样旧走廊不会单独惩罚通向新分支的路径。

## 四、今日代码改进内容

1. 调整全局代价默认参数

将 `start_debt_weight`、`start_overlap_weight`、`edge_debt_weight`、`edge_overlap_weight`、`edge_region_switch_weight`、`edge_return_weight` 的默认值调整为 0。默认情况下，全局规划主要保留原始 FUEL 代价、近距离 bonus、凹陷区域代价和狭窄通道代价。

2. 限制局部 closeout 数量

将每轮局部 closeout 最大数量限制为 1，避免多个局部修复目标连续插队，打断正常的局部多视点探索顺序。

3. 禁用 debt-only 遗忘触发

`debt_score` 不再单独触发遗忘标记。遗忘标记现在主要来自三类证据：前沿 stale、路径覆盖重叠、近距离多次经过但进展不足。

4. 强化 cooldown

处于 cooldown 的前沿默认不能再次进入 closeout，除非它具有很强的覆盖证据并且距离无人机非常近。这样可以减少同一低进展目标被反复尝试。

5. 新增 tail overlap 计算

新增 `computePathTailOverlap()`，只统计路径末端短距离内的重复覆盖情况。该指标比整条路径 overlap 更适合判断目标附近是否重复访问。

6. 新增 branch hysteresis

在局部前沿排序中加入分支保持逻辑。系统会根据前沿相对于无人机的位置角度生成 `branch_id`，并维护 `active_branch_id`。在保持窗口内，优先探索当前 active branch 内的前沿，减少岔路口来回跳变。

7. 扩展调试日志字段

`local_view_log.csv` 新增 `branch_id` 和 `active_branch_id` 字段，用于后续判断无人机是否仍在岔路口频繁切换分支。`frontier_track_log.csv` 和 `start_cost_log.csv` 继续记录 debt、coverage、progress、cooldown 等信息，方便下一轮数据分析。

## 五、期望达到的效果

1. 减少岔路口局部最优

通过 branch hysteresis，让无人机在岔路口能够连续几轮保持同一探索分支，避免每轮因为局部代价细微变化而改变方向。

2. 减少假遗忘目标

禁用 debt-only 遗忘触发后，预期 `forget_reason=4` 应该消失。只有具有真实 stale、覆盖重叠或近距离低进展证据的前沿才会被作为遗忘区域处理。

3. 降低无效局部回头

每轮最多只允许 1 个 closeout 目标插队，且触发条件更严格。预期 `selected_reason=2/3` 在局部第一目标中的比例会下降，局部规划不再频繁围绕低收益目标重规划。

4. 保留原始 FUEL 全局探索稳定性

全局 ATSP 边默认恢复原始 FUEL 代价，避免 experimental cost 对远距离前沿排序产生过强干扰。这样应该能帮助无人机重新走出岔路口，继续向未知区域推进。

5. 为后续减少远距离回头打基础

本次修改不是最终版本，而是先解决“岔路口卡死”和“假遗忘过多”的稳定性问题。只有在无人机能够稳定完成探索后，才能继续分析远距离回头产生的真实原因。

## 六、当前验证情况

今日代码已经完成编译验证，`catkin_make` 编译通过，没有出现新的编译错误。编译过程中仍存在原工程已有的 warning，例如 unused variable、signedness comparison 和格式化 warning，但这些不是本次修改引入的启动阻塞问题。

需要注意的是，本次修改后的真实探索效果还没有通过新一轮实验数据验证。因此当前只能确认代码可以正常编译，不能直接宣称重复访问问题已经解决。

## 七、下一步计划

1. 重新运行完整探索实验

使用今天修改后的版本重新跑一轮探索，观察无人机是否能够走出岔路口，并完成更长时间、更大范围的未知区域探索。

2. 对比新旧日志指标

重点分析 `frontier_track_log.csv`、`local_view_log.csv`、`start_cost_log.csv` 中以下指标：

- `forget_reason=4` 是否消失；
- `selected_reason=2/3` 作为局部第一目标的比例是否下降；
- 同一 `sig` 是否仍然连续多轮排在局部第一；
- `progress_delta=0` 但 `attempt_cnt` 持续增长的情况是否减少；
- `branch_id` 和 `active_branch_id` 是否在岔路口频繁跳变。

3. 根据实验结果调参

如果仍存在岔路口摆动，可以进一步增大 `branch_hysteresis_rounds` 或调整 `branch_hysteresis_angle`。如果无人机过于固执地沿某个分支走，可以缩短保持轮数，或者加入分支收益衰减机制。

4. 继续分析远距离回头问题

如果无人机能够稳定完成探索，但仍然存在明显远距离回头，则下一步需要重新引入更温和的全局区域完成度约束，而不是简单依赖 debt_score。可以考虑基于区域完成率、分支完成率或 frontier 生命周期构造全局惩罚。

5. 建立更明确的重复访问评价指标

后续应将重复访问从视觉现象转化为量化指标，例如路径网格重复覆盖率、单位新增未知体素路径长度、同一区域回访间隔、远距离回头次数等。这样可以更客观地判断每一版优化是否真正减少了重复访问。

## 八、今日结论

今天的主要结论是：上一版算法的问题不在于局部回头机制本身，而在于局部修复触发过于激进，并且全局代价中的 overlap/debt 项在岔路口场景下干扰了正常分支选择。因此本次优化采取稳定性优先策略，先降低假遗忘和局部插队的影响，同时加入分支保持机制，使无人机能够在岔路口持续推进。

下一轮实验的重点不是只看路径是否重叠，而是先确认无人机是否能够摆脱岔路口局部最优。如果能够稳定推进，再继续针对远距离回头问题做全局层面的重复访问抑制优化。
